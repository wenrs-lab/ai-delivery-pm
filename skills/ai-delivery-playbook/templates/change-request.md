## 二、影响评估（项目经理填写，结论先行）

| 维度 | 评估 |
|------|------|
| 范围 | 新增任务包：__________；是否触碰 Out of Scope： |

| 资源 | 需抽调角色与人日；是否与其他并行项目冲突： |
| 质量/技术 | 对架构、数据、模型效果、测试回归的影响： |

| 综合结论 | 🟢 可直接接 / 🟡 有条件接 / 🔴 不建议接 |

## 三、五种处置选项（每次都要给全，让对方做选择题）

| 选项 | 说明 | 代价 | 适用 |
|------|------|------|------|
| A 接受，不变基线 | 有缓冲且不动关键路径 | 无 | 小改动 |
| B 换期 | 接受范围，顺延里程碑 | 验收日后移 X 天 | 客户更看重功能 |
| C 换范围 | 保持工期，砍掉等量优先级低的需求 | 需客户/销售签字确认取舍 | 日期刚性 |
| D 分期 | 本期最小可用，余量进下期/二期 | 需明确二期承诺边界 | 最常见 |
| E 拒绝 | 技术不可行 / 超产能 / 合规不允许 | 需给替代方案与解释 | 不合理承诺 |

## 四、对销售沟通话术框架（可直接复制）

```
【事实】目前项目基线是 ____，关键路径上 ____ 已完成 ____。
【影响】这个需求会占用 ____ 人日，导致 ____ 里程碑后移 ____ 天 /
        需要砍掉 ____ 才能守住 ____ 日期。
【选项】我们可以：A ____ / B ____ / C ____，我建议 ____，
        因为 ____。
【需要你决策】请今天下班前确认选哪个，以及由谁同步给客户；
        在确认前，我不会把它排进迭代，也不会对外给时间点。
```

原则：**敢说"不"，但把"不"包在方案里**；不评价销售的对错，只讲事实、影响和可选路径；把对外承诺权收归统一出口。
